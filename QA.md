# Verification contract

## Scope and limits

The supported target is macOS 12.3 or later. The source language policy is
ES2022, with a Safari 15.4 build target and a separate built-in availability
check. These checks are not polyfills or proof of every native host behavior.
Compatibility on macOS 12.3 and macOS 15 is accepted as a target assumption.
Automated native CI uses macOS 15; target-floor checks do not establish full
interactive behavior on every supported host.

The current artifact has been driven through the real Shortcuts helper using
Term At Target's installed integration harness. The helper exposes the native
settings form, completion and custom progress panel, but does not draw JXA
`Progress` or provide its Stop control. The action therefore uses only its own
panel, with a native Stop button. Live stopping preserved saved PDFs and
reported cancelled and not-started work separately. The panel hides for modals
and closes before completion.

Downloads recovery has also been exercised inside
`com.apple.WorkflowKit.MacHelper`: a validated PDF with an unwritable requested
destination was published and confirmed in the user's Downloads folder under
its intended filename. An inaccessible Downloads folder still requires the
confirmed-copy temporary-folder fallback; a test of one host's permissions does
not guarantee permission on every installation.

Live stepwise fallback in a host genuinely lacking form capability remains
unverified. Native applet tests, port tests and offscreen layout do not establish
that host-specific condition.

## Automated gates

From the setup in [CONTRIBUTING.md](CONTRIBUTING.md):

```sh
npm run quality
npm run test:integration:macos
```

`quality` does not rebuild first. It must detect a stale committed `dist/`.
Use `npm run build` when intentionally regenerating JXA and checksums, then
verify that generated files are included in the reviewed change.

| Check | Requirement |
| --- | --- |
| Source/static policy | Recursive discovery, syntax, hygiene, metadata/toolchain/URL consistency, import boundaries and executable registry |
| Language target | Source and artifact syntax plus supported built-ins at the declared floor |
| ESLint | `js.configs.all`, with individually justified exceptions and tuned rules |
| Shell/workflows | Shell syntax and ShellCheck; actionlint when installed |
| Unit/repository tests | Complete discovered suites with failures and skips inspected |
| Coverage | 100% line, branch and function coverage for core, application and backend |
| Mutation | Minimum score 96 for core, application and backend; unit tests exercise mutated sources |
| Distribution | Generated bytes match source, checksum, licensing and metadata |

The toolchain declarations and configuration are authoritative:
`package.json`, `package-lock.json`, `.node-version`, `mise.toml`,
`eslint.config.mjs`, `stryker.config.json` and `tools/lint.mjs`.
Reports are generated under ignored `reports/`; they are verification artifacts,
not current product documentation.

## Native suites

`npm run test:integration:macos` runs these scripts in sequence:

| Script under `tests/integration/` | Coverage |
| --- | --- |
| `macos.sh` | Actual production entry, dimensions, placement, compression, validation and source integrity |
| `background.sh` | Alpha flattening, background and colour/profile behavior |
| `selection.sh` | Folder traversal, overlap, identity, links, packages and explicit selections |
| `publication.sh` | Occupied entries, permissions, ownership and recoverable failures |
| `volumes.sh` | Cross-volume APFS and HFS+ publication in both modes |
| `cards.sh` | FAT32 exclusive publication/collisions and exFAT recovery in both modes |
| `damaged.sh` | Damaged-source refusal and combined/separate behavior |
| `form.sh` | Explicit production-renderer probe, native geometry/accessibility and PNG previews |

Install the complete native tool set from the contributor guide. Volume tests
require permission to create and attach disk images. Inspect and report every
skip; inability to attach a volume is not a passing filesystem result.

Published PDFs require exact page counts and strict pdfcpu validation.
Independent qpdf structure checks and Poppler rendering/pixel assertions provide
checks beyond the PDF-producing backend. Source hashes must remain unchanged.

Set `IFTP_FORM_PREVIEWS` to an external output directory to retain form captures.
Review normal, correction, deep-path/error, multiple-destination and large-detail
states in Aqua and Dark Aqua. Controls/actions must fit within 744 points.
Composite RGBA captures over the correct native appearance background before
visual review. Confirm full detail remains selectable and scrollable; geometry
alone does not establish live interaction.

## Failure and concurrency qualification

Use independent fixtures, expected results and positive controls. Record the
artifact hash, exact commands, environment, exit statuses, discovery/skips and
full relevant failures. Keep run-specific evidence outside operational docs.
Required scenarios include:

- Supported still-image formats, actual loader/type checks, animated/multipage
  refusal, corrupt/unknown metadata, EXIF orientation, ICC, alpha and scaling.
- Strict settings types, unknown fields, timestamp presence, canonical defaults
  and GUI/headless value equivalence.
- Source changes around capture and after capture; inspection/rendering must use
  identical private bytes. A stability injection must prove it actually ran.
- Queue page/byte/argv boundaries, oversized pages, exact final count, failed
  imports and cleanup. Measure retained page records/bytes separately from RSS.
- At least 12 two-process publication rounds per mode, with unique actual paths,
  valid complete PDFs and preservation of occupied entries.
- Ownership before creation and faults at registration, validation transition,
  release, disposal and reporting. After a confirmed validation, a reported
  recovery must exist and hold the expected validated bytes in both modes.
  Include faults after an earlier separate-mode commit and positively assert
  that each injection executed.
- Cancellation before and after commit, retained saved/recovered records,
  truthful unattempted work and bounded faults from optional observers.
- Fresh Linux/macOS dependency restores with `npm ci --ignore-scripts`, identical
  generated bytes, actual JXA execution and operation without Node on PATH.

Native fault probes use explicit entry files importing production modules under
the production bundler configuration. Do not expose private product APIs or
append private global calls to a production bundle. End-to-end corpus tests
must invoke the actual production artifact.

## Live Shortcuts acceptance

Use an isolated temporary Shortcut with the complete current generated script
and synthetic local inputs. Preserve the user's production Shortcut and restore
only preference changes caused by the test.

Verify selection consent, all six controls, keyboard navigation, full-detail
selection/copy/scrolling, Create and Cancel. Enter Maximum resolution `1018`, JPEG quality `101` and
background `purple`: all three errors must appear while other draft choices
remain. Correct the fields and complete conversion; verify the actual saved
PDF, output count and truthful completion. Check canonical recall on another
run and that interactive return creates no text-result files.

Exercise visible progress and Stop during actual work, including committed
outputs and retained validated work. Exercise stepwise fallback on an accessible
intended host where the native form capability is genuinely unavailable;
programming faults must be diagnosed rather than treated as unavailable UI.

Remove the temporary Shortcut after testing. A helper access timeout is an
unperformed check, not a passing UI test or proof that product code hangs.
